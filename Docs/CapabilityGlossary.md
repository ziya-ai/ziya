# Ziya Capability Glossary

This file is a **reader-vocabulary -> Ziya-name** cross reference. Ziya's own
docs describe capabilities by their internal mechanism name; this glossary lets
a reader who searches by the *vocabulary they already know* (a competitor's
term, a plain-English phrase) land on the right Ziya capability and its detail
in [Capabilities.md](Capabilities.md).

The region between the two `GENERATED` markers below is produced mechanically
from the capability ledger (`19-ziya-ledger.json`) and the capability matrix
(`30-matrix.json`). **Do not hand-edit inside the markers** -- your changes
will be overwritten. To regenerate after the ledger changes:

```
python3 scripts/complandscape_docdefects.py glossary --write
```

Everything *outside* the markers (this preamble and the "Terms competitors use"
section) is hand-maintained and preserved by `--write`.

## Terms competitors use

Some capabilities that read as gaps against a competitor's vocabulary are
actually shipped under a Ziya-internal mechanism name. This table maps the
**competitor's word** (and the tool it comes from) to the Ziya mechanism and
its **critic-corrected** status. Five rows were downgraded from FOUND to PARTIAL
by Critic A because a partial-match mechanism had been stretched to a full
match; a sixth (user-authored project rules) keeps its FOUND verdict but has its
score capped below the roster leader. Those rows say what is missing. Rows
marked _experimental_ name code
that exists but is **not wired at runtime** — documented here for vocabulary
mapping only, not as shipping capabilities.

Status is stated at the ledger's maturity after critic correction; it is never
raised above it. Where the match is partial the row says what is present and
what is absent.
